## Review method

- Read the authoring and engine contracts, including all of `docs/card-dsl.md`,
  and inspected all 22 changed `scriptgen` files. Parser forms that were not
  read completely had to remain honest stubs rather than silently lose fields,
  alternatives or controller scope.
- Checked the changed DSL and engine mechanics against the official
  Comprehensive Rules dated 2026-09-25. This included entwine (CR 702.42a),
  affinity (CR 702.41a), linked exile (CR 400.7 and 607.2a), cost determination
  (CR 601.2f and 602.2b), continuous-effect affected sets (CR 611.2c), and
  layer dependency/timestamps (CR 613.6). The review also covered projection
  invalidation, `locks_its_set` versus `Modifier::layer()`, state hashing,
  deterministic ordering and exact-incarnation/LKI tracking.
- Mapped all 386 implementation-like changed cards to their canonical tests.
  The Oracle/test audit identified 197 multi-clause cards with a single test.
  Thirty-seven high-risk cases were read in full; the other 160 were reviewed
  through a per-card extraction of their Oracle text, test names, behavioral
  events and assertions, with full-file follow-up for every suspicious case.
- Ran a second pool-wide clause scan over the implemented changed cards for
  keyword and negative-clause evidence. This exposed additional missing
  keyword assertions and every implemented `can't be regenerated` test that
  lacked an actual regeneration shield. False positives such as Reach versus
  Flying and tests that already had a non-flying control were checked directly.
- Ran no full code generator and used no external card-script corpus. Mobile
  and the experimental web client were excluded as instructed. Review fixes
  did not modify `baylee-train`.
