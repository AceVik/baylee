# Client UX/UI review — 2 October 2026

User scope: improve gameplay and the lobby, with screenshot iterations;
compact chosen types and charge counters. Font replacement is permitted
where readability, density and licensing justify it. Preserve clear game
state and full card-art notices. This pass follows the feedback fixes and
precedes historical set completion.

### Iteration 2 — waiting room

At 1280×800, the second player was mostly below the fold. Each seat used
separate rows for the player name, readiness, deck name and a full-width deck
button, plus a permanently open empty starting-card search. Readiness looked
like an actionable button although clicking did nothing. Scrolling also
removed the Start action from view.

The revised seats group identity/readiness and deck/deck-picker together.
Readiness is a text badge. Team and AI controls share a wrapping row. Starting
cards have a per-seat expander with their count always visible; expanding a
second seat preserves the draft and search text and removes hidden input focus.
The room header stays above the desktop/tablet scroller, with a visible scrollbar.
Native comparison confirms both decks, AI selection and both life controls
are visible at 1280×800. The final refinement brightens readiness text, reduces
inter-section spacing and uses offline-specific room guidance. Online host
succession is no longer explained in the offline room.

### Iteration 3 — adjacent counters and hover previews

A real room setup gives Forest, Island and Mountain one charge counter each.
The initial screenshot shows the compact labels work side by side. Hovering
Island exposes a defect: its enlarged card preview covers most of “1 Ladungsmarke”.
The placement now treats preview rectangles and earlier labels as occupied,
keeps label rectangles within the window and uses measured text dimensions
once available. A renderer-independent placement module tests all four window
edges, successive labels and the preview collision.

The selected-deck overview now uses existing `copies` / `side_copies` totals
instead of counting stored text lines. Older gateway responses without totals
retain the explicitly named row-count fallback. The house-library catalog
still reports rows because that API only supplies row counts; no counts are
invented. Gateway and offline selected-deck summaries both already supply totals.

Baseline screenshots: /private/tmp/baylee-ux-counter-crowd-before.png and
baylee-ux-counter-hover-before.png. The first corrected screenshots are

The deck-count screenshot is /private/tmp/baylee-ux-deck-count.png: Allytifact

### Iteration 4 — login hierarchy and keyboard navigation

The 1280×800 baseline put the beta key and guest form before account sign-in,
leaving the password partly clipped and the submit button below the viewport.
Username, password and Sign in now precede the optional guest path. The beta
key remains above account creation on the registration view. Native screenshots
confirm Sign in is visible without scrolling and both guest entry and registration
actions remain reachable by scrolling. No account was created or submitted.

The room expander review also found that Tab still visited collapsed starting-card
inputs through the core's older, unconditional field ring. The client now includes
only the expanded seat's search and open counter editor. Regression coverage drives
real keyboard messages forward and backward, including collapse after editing.
Account Tab order follows the new visual order for sign-in and registration.

Evidence: /private/tmp/baylee-login-layout-before.png,
baylee-login-layout-after.png, baylee-login-guest-after.png,
baylee-login-register-after.png and baylee-login-register-scrolled.png.
Validation: 112 core lobby tests and 153 client lobby tests pass; dev-control
all-targets clippy and the native build pass. Build emits the existing macOS
large-unwind-section linker warning. Logs: /private/tmp/baylee-login-layout-clippy.log
and baylee-login-layout-build.log. Existing bundled fonts, glyphs and legal footer
are unchanged; this iteration adds no asset or licence dependency.

Native keyboard follow-up: with both starting-card sections collapsed, Tab keeps
